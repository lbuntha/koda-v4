Koda launch guide

How to open Koda to its first families, how to keep adding content from Grade 1 upward, and how to find and win the first clients. Written 2026-10-31 from the code and the live deployment.

The path 1. Where it stands 2. Before the first user 3. Growing the content 4. Releasing and rolling back 5. Running it 6. Finding clients 7. The first pilot 8. Open items

The whole path in six steps

  1. Set upAdmin account, email, Ask Koda on or off, menu labels.Done when: a real test email arrives
  2. Put content inPublish Rebus; import Library books and Trace sets.Done when: a child account sees them
  3. Test on a real phoneInstall, go offline, check push, run one family end to end.Done when: nothing sticks
  4. Choose who to inviteStart with parents of Grade 1–3 children you can talk to.Done when: 20–30 families said yes
  5. Run a 4-week pilotHelp in week 1, add one piece of content a week, then call each family.Done when: you have the five numbers
  6. Decide: go, fix, or rethinkThen open to the next group.Done when: you chose
Then repeat every week: finish one book or trace set → publish → import (section 3) → look at it as a child → read the parent reports → pick next week's content.
Who does what. You own all content (books, pictures, trace sets, Rebus approval, accounts, email) and the business side. Claude owns code and features. Where a step says You, it needs your judgement or your credentials. The client section (6 and 7) is a set of proposals to test, not facts about the market.

2. Before the first user

Do these in order. Nothing here needs new code.

  • YouMake sure an admin account exists on production. Sign in at the web address above with it. If you do not have one, create it against the production database (needs MONGODB_URI, kept in the repository secrets): 
    cd server
MONGODB_URI='<production uri>' MONGODB_DB=koda_v4 \
  python -m app.cli create-admin --email you@example.com --password '<strong password>'
  • YouConfigure email. In GitHub: repository variables MAIL_DRIVER=smtp, SMTP_HOST, SMTP_PORT, SMTP_STARTTLS, MAIL_FROM (an address on a domain you control, not koda.local), and secrets SMTP_USER, SMTP_PASSWORD. Push to main to deploy. Until this is done the weekly summary and password reset reach nobody. Turn on REQUIRE_EMAIL_VERIFICATION=true only after a real test email arrives.
  • YouDecide Ask Koda for launch. In the app: Ask Koda page (the same place holds the mascot switch). Switch the master ai.enabled off to launch without the live voice coach and the tutor; the Koda character stays on screen as a friendly face, or hide it with the mascot switch. The Gemini and Anthropic keys are billed; leave them off until you want that cost.
  • YouPublish Rebus. Rebus Studio → approve all → publish a release. Until you do, Rebus Rush is empty for every child. Check the grade of each batch before approving (see section 3).
  • YouPut Library and Trace content on production (section 3). Without it the Library shows only the starter books bundled in the app and Trace has no sets.
  • YouFix the menu labels that were typed wrongly in your local data (LEADERBOAR, SKILLS STU, LIBRARY STU). On production, open the Menu page and check each label. The defaults in the code are correct.
  • YouTest on a real phone with a poor connection: install the app to the home screen, open a lesson, switch on airplane mode, open it again. Then check a push: turn notifications on for a parent account and trigger one.
  • YouRun one family end to end. A child plays a lesson; the parent receives the weekly summary by email and a push, in the parent's language.
  • YouPrivacy and consent. The users are children. Have a privacy policy and a clear parent-consent step ready, and check what the rules in Cambodia (and in any other country you open in) require. The repository has docs/SECURITY.md and docs/LEADERBOARD_PRIVACY.md to start from; they are engineering notes, not legal advice.

3. Growing the content from Grade 1

The platform is finished enough that growth is content work. Everything below follows one rule: author it in a Studio, publish it, and children get it. Grades are ages minus five: Grade 1 is age 6, Grade 2 is 7, Grade 3 is 8. Studios speak grades; the data stores ages.

Two ways to get content onto production

A. Author on production directlyB. Author locally, then move with a content pack
HowSign in to the live app as admin and use Library Studio, Trace Studio and Rebus Studio there.Work on localhost:3001, then export and import.
Good forSmall edits, fixing a typo, quick additions.Big batches you want to review first; keeps a copy on your machine.
Watch outEvery save is live to children once published.The import never overwrites a correction made on the server unless you pass --update.

The content pack (way B)

# 1. publish in the Studio first: only published content is exported
# 2. export from the local stack
docker compose exec api python -m app.cli content-export /tmp/pack
docker compose cp api:/tmp/pack ./content-pack        # the folder is ignored by git

# 3. try it on production without writing anything
cd server
MONGODB_URI='<production uri>' MONGODB_DB=koda_v4 \
LIBRARY_AUDIO_BUCKET=learn-with-koda-library-audio \
  python -m app.cli content-import ../content-pack --dry-run

# 4. do it for real (re-running is safe: it adds only what is missing)
  python -m app.cli content-import ../content-pack
# later, to take newer revisions of books you already imported:
  python -m app.cli content-import ../content-pack --update
Not yet tried against production. The round trip is tested against a scratch database, but writing audio to the Cloud Storage bucket from your machine needs Google credentials (gcloud auth application-default login). Do the --dry-run first and check the counts before the real import.

Per pillar

Reading — Library

  • The plan is 12 Grade 1 books, one at a time: docs/library-grade1-books-plan.md. Each follows the same loop: brief, story, title check, questions, JSON, check, register, pictures, read it at 390 px. A book is done when step 8 passes.
  • Book 1 (Bot and the Seed) is published. Book 2 (Sleepy Night Animals) waits for pictures.
  • Grades 2 and 3 have no book plan yet. Copy the Grade 1 plan, raise the sentence length and the vocabulary, and set ages to [7,9].
  • Pictures and recordings travel with the book in a content pack, keyed by their hash, so a book never arrives without its art.

Drawing — Trace

  • English A–Z, a–z and 0–9 are drafted: docs/ENGLISH_TRACE_PLAN.md. Finish the tests and grades on each set, then publish.
  • Khmer consonants and vowels follow the same Studio route. Children's tracing progress stays on the child's device and syncs to the parent report; it is never part of a content pack.

Rebus

  • The server seeds 2,324 puzzles as drafts on every boot (create-if-absent, so your edits are never undone). Approve and publish in batches by grade rather than all at once if you want to control what a Grade 1 child meets first.
  • Puzzles carry an age range. Of the 2,324, 1,878 start at age 9 or younger. Spot-check the reading level of the math and quiz puzzles at Grade 1 versus Grade 3.

Math and the other skills

  • The lessons exist and are age-gated. Walk the course once as an age 6, 7 and 8 child to confirm there is a path with no dead end.
  • New lessons or a whole new skill: docs/SKILL_DEVELOPMENT.md and docs/NEW_SKILL_PROMPT.md. After a new skill is added, the API needs a restart to register it. Grade 4 to 6 content slots into the same age bands, so nothing already shipped changes.

4. Releasing and rolling back

Shipping a code change

  1. Make the change on main locally and commit.
  2. npm run lint and the scoped tests for what changed; the full npm test when the machine is quiet.
  3. Pushing to main deploys. The pipeline runs CI (about 37 minutes), then deploys the API, the web service and the Firebase routing (about 5 minutes more).
  4. Watch it: gh run list --limit 3, then gh run view <id>.
  5. Confirm the new revisions are ready: 
    gcloud run services describe koda-app --region us-central1 --project learn-with-koda \
  --format='value(status.latestReadyRevisionName)'
A phone that already has the app keeps the old version until the update prompt is accepted. Children never lose a round to an update: the new version waits until they choose it.

Rolling back

If a deploy goes wrong, send traffic back to the last good revision (no code change needed):

gcloud run revisions list --service koda-backend --region us-central1 --project learn-with-koda
gcloud run services update-traffic koda-backend --region us-central1 --project learn-with-koda \
  --to-revisions=<previous-revision>=100

Same for koda-app. Revisions before this release were koda-app-00192-dqp and koda-backend-00243-7fz. A code tag, pre-mvp-cut, marks the repository before the clean-up if you need to look back.

6. Finding clients

These are proposals, not facts. I have no market research, pricing data or user numbers for Cambodia. Treat every statement below as a hypothesis to test with a small pilot (section 7), and replace it with what you learn.

Who it is for

SegmentWhy they might want KodaWhat to prove
Parents of children in Grades 1–3 (start here)They want to know how their child is doing without sitting next to them. Koda's weekly summary and daily reminder do exactly that. Khmer and English, works offline, a free plan.The child practises on their own at least 3 days a week; the parent opens the summary.
Teachers and small classesRebus group rooms and a progress view suit a classroom; the content follows the national-style grade bands.A teacher can run a 20-minute session with a shared phone or tablet.
Tutoring and learning centresThey need structured practice they can hand a child. Many children, few staff.The centre keeps using it without you in the room.
Khmer families abroad (later)Children who need reading and numbers in Khmer. Offline use and the Khmer letters matter.Only after the Cambodian pilot works.

What to say

  • For the parent: "Your child practises maths and reading for a few minutes a day, and you get a short message about how it went." Lead with the summary, not the features.
  • For the teacher: "Twenty minutes of practice that follows your grade, in Khmer, with nothing to set up."
  • Always true and checkable: works without internet after the first visit; free plan; no ads; progress visible to parents.

Where to reach them (to verify)

  • Where parents already talk: parent groups and school groups on the messaging and social apps your friends and relatives actually use. I believe Facebook and Telegram groups are common for this in Cambodia; check this with the parents you know before spending any time.
  • Through schools: ask one teacher you know to try it with one class for four weeks. A teacher who sees children asking to continue is the best introduction to the next school.
  • Through your own network first: 20 to 30 families you can talk to. They will tell you what is confusing in the first minute.
  • A short demo: a one-minute screen recording of a child finishing a lesson and the parent's summary arriving. This is the clearest sales material you can make.

Free plan and paying

  • The app has plans and billing in place, and users start on the free plan. Decide before the pilot what stays free forever (I suggest: the core Grade 1–3 practice) and what a paid plan adds (for example more children, richer reports, Ask Koda).
  • Do not charge in the pilot. Ask instead: "Would you pay for this, and how much?" Their answers set the price, not a guess.

Privacy as a selling point

Parents and schools care what happens to a child's data. Say plainly what you collect, that there are no ads, and who can see a child's progress. The leaderboard design already limits what is shown (docs/LEADERBOARD_PRIVACY.md).

7. The first pilot

ItemPlan
Size20 to 30 families, or 2 to 3 classes. Small enough to talk to everyone.
Length4 weeks.
Before it startsAll of section 2 done, especially email, a real phone test, and enough content: Rebus published, at least 2 to 3 Library books, one Trace set.
Week 1Help each family install it to the home screen and sign in. Watch for where they stop.
Weeks 2–3Do not change much. Fix only what blocks children. Add one new piece of content each week and see if it gets used.
Week 4A short call with each family: what did the child ask to do again? What did the parent ignore? Would they pay, and how much?

What to measure

MeasureWhy
Children who practised in each of the 4 weeksRetention, the number that matters most.
Days practised per child per weekWhether it became a habit.
Lessons finished versus startedWhere lessons are too hard or dull.
Parents who opened the weekly summaryWhether the core promise lands.
Where the app got stuck or failedReal phones on real networks.

I have not checked whether the admin pages give you a view across all users. The per-child learning log and the parent report exist. If you need an overview across the whole pilot, tell me which numbers above you want on one screen and I will build it.

Decide at the end

  • Go: most children still practise in week 4, and parents say they read the summary.
  • Fix first: children start but stop. Look at where and fix that, then repeat with new families.
  • Rethink: children do not start. The problem is in the first minute or in how you reached them, not in the content.
